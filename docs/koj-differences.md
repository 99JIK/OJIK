# KOJ와의 차이

[README](../README.md) | [아키텍처](architecture.md) | [채점 파이프라인](judge-pipeline.md)

[KOJ](../../KOJ/)를 참고해 다시 설계했습니다. 무엇을 왜 바꿨는지입니다.

KOJ의 결함 목록은 [`KOJ/docs/known-issues.md`](../../KOJ/docs/known-issues.md)에 있습니다.
아래 표의 번호는 그 문서의 번호입니다.

## 알려진 결함의 처리

| KOJ 결함 | 여기서 | 방식 |
|---|---|---|
| 1. MQ 연결 실패 시 제출 유실 | 발생 불가 | INSERT가 곧 큐 등록. 저장과 큐가 어긋날 수 없음 |
| 2. Recover 미들웨어 미등록 | 해결 | `app.onError`가 모든 예외를 500으로 변환 |
| 3. 설정 읽기 실패 시 계속 진행 | 해결 | zod 파싱 실패 시 즉시 종료. 항목별 이유 출력 |
| 4. 종료 시그널 처리 없음 | 해결 | SIGTERM에 진행 중인 채점을 마치고 나감 |
| 5. 작업 디렉터리를 비우지 않음 | 해결 | 박스 대여 시 `--cleanup` 후 `--init`. 재채점은 이전 결과를 먼저 삭제 |
| 6. 미지원 값에서 nil 역참조 | 해결 | `requireLanguage`가 던짐. 제출 단계에서 이미 거부됨 |
| 7. 상태 코드 없는 오류의 원문 노출 | 해결 | fetch 실패를 한국어 안내로 변환 |
| 8. 지원 언어 하드코딩 | 해결 | [`languages.ts`](../packages/core/src/languages.ts) 한 곳. 6곳 -> 1곳 |
| 9. 큐 메시지가 영속화되지 않음 | 발생 불가 | 큐가 DB 행. 영속성이 기본 |
| 10. 재채점 수단 없음 | 해결 | 제출별, 문제별 재채점 API |

## 구조 변경

### 저장소

KOJ는 네 저장소였고 셋이 `koj-backend`에 Go module로 묶여 있었습니다. 백엔드의 entity를 고치면
워커와 채점 이미지의 module 버전을 각각 올려야 반영됐고, **잊으면 아무 에러 없이 옛 구조체로
동작**했습니다.

여기서는 한 저장소에 npm workspace입니다. 스키마를 고치면 API, 워커, 프론트가 **컴파일 시점에**
깨집니다. 계약 파손이 조용히 넘어갈 자리가 없습니다.

### 메시지 큐 제거

RabbitMQ를 없애고 제출 테이블을 큐로 씁니다. 근거와 절충은
[채점 파이프라인의 큐 절](judge-pipeline.md#큐를-db에-둔-근거)에 있습니다.

운영에서 컨테이너 하나, 설정 파일 하나, 장애 지점 하나가 줄었습니다.

### 채점 이미지가 사라짐

KOJ의 `koj-judge-image`는 컨테이너 안에서 도는 **Go 프로그램**이었습니다. 워커가 작업 디렉터리를
만들어 두면 그 프로그램이 metadata JSON을 읽어 컴파일하고 실행하고 결과 JSON을 남겼습니다.

여기서는 그 프로그램이 없습니다. 워커가 호스트에서 `docker exec`으로 `isolate`를 직접 부릅니다.
러너 이미지는 컴파일러와 `isolate`만 담은 껍데기입니다.

얻은 것:

- 제출자 코드가 도는 컨테이너에 우리 런타임이 없음
- 채점 로직 전체가 한 프로세스에 있어 디버깅 지점이 하나
- 파일 기반 프로세스 간 통신(metadata JSON, result JSON)이 통째로 사라짐

잃은 것: **작업 디렉터리만으로 단독 재현**이 안 됩니다. KOJ는 문제가 된 제출의 디렉터리를
그대로 `docker run` 하면 재현됐습니다. 여기서는 워커를 거쳐야 합니다. 실용적으로는
`scripts/smoke-judge.sh`가 같은 명령을 손으로 칠 수 있게 보여주는 것으로 대신합니다.

### 이미지 분할

KOJ는 gcc, g++, JDK 24, python, node, strace를 한 이미지에 담고 제출마다 그걸 띄웠습니다.
여기서는 언어별로 쪼개고 상주시킵니다.

### 테스트케이스를 복사하지 않음

KOJ `worker/prep.go`는 제출마다 다음을 실행했습니다.

```bash
cp -r {Static}/problem/{id}/tc {Static}/submission/{submissionId}/tc
```

영구 디스크에 복사하고 지우지 않았습니다. static 볼륨이 46GB가 된 경로입니다.

여기서는 문제 디렉터리를 읽기 전용으로 붙이고, 실행 직전에 해당 케이스 **한 개만** tmpfs 박스에
복사합니다.

### 스키마 관리

| | KOJ | 여기 |
|---|---|---|
| 스키마 주인 | 백엔드 기동 시 `AutoMigrate` | 마이그레이션 SQL 파일 |
| 이력 | 없음 | `packages/db/drizzle/`에 커밋됨 |
| PG enum | 손으로 `create_enum.psql` 적용 | 마이그레이션에 포함 |
| 되돌리기 | 불가 | 파일이 있으니 가능 |
| 파일 참조 | 경로 문자열 | sha256 + 크기 |

마지막 항목이 실질적입니다. KOJ는 백업에서 DB만 되돌리면 행은 있고 파일이 없는 상태가 되는데
그걸 알아챌 방법이 없었습니다. 해시가 있으면 [`npm run check:data`](../scripts/check-data.ts)가
파일 없음과 내용 다름을 구분해 짚어 줍니다.

### 상태와 판정의 분리

KOJ는 `SubmissionStatus` 하나에 진행 상태와 결과가 섞여 있었고, 최종 집계가 **전 케이스
accepted가 아니면 전부 `wrong_answer`** 였습니다. 시간 초과도 메모리 초과도 화면에는
틀렸습니다로 나왔습니다. 유형별 개수는 따로 저장했지만 학생은 못 봤습니다.

여기서는 `status`(진행)와 `verdict`(결과)가 별개고, 케이스 결과 중 **가장 나쁜 것**이 제출의
판정이 됩니다.

### 성적 산출 규칙

KOJ `ScoreService.go`는 문제별로 **최고점이 아니라 마지막 제출** 하나만 셌습니다. 맞힌 뒤
실수로 다시 제출하면 점수가 사라졌습니다.

여기서는 문제집 진행 현황이 **기한 안에 정답 제출이 하나라도 있으면 푼 것**으로 셉니다. 한 번
맞히면 유지됩니다. 규칙은 [`problemsets.ts`](../apps/api/src/routes/problemsets.ts)의 progress
쿼리에 주석으로 박아 뒀습니다.

### 프론트

| | KOJ | 여기 |
|---|---|---|
| 프레임워크 | React 18 + Chakra UI 3 | SvelteKit + Tailwind |
| API 호출 | `src/api/` 아래 도메인별 함수 60여 개 | [`api.ts`](../apps/web/src/lib/api.ts) 하나 |
| 토큰 | `sessionStorage`, 함수마다 헤더 직접 구성 | httpOnly 쿠키, 스크립트가 못 읽음 |
| 공통 인터셉터 | 없음 | 401 처리, 네트워크 오류 변환 |
| 언어 선택지 | 모달 3곳에 배열 복사 | `GET /api/languages` |
| API 주소 | `Config.tsx`에 하드코딩 | `VITE_API_BASE` |
| 에디터 | 없음 (파일 업로드) | CodeMirror 6, 지연 로드 |

번들은 라우트별 첫 로드 기준 **32-40 KB gzip**입니다. 측정 방법은
[개발 환경](development.md#번들-크기)에 있습니다.

### 인증

| | KOJ | 여기 |
|---|---|---|
| 역할 | admin, professor, ta, student | admin, staff, user |
| 권한 판정 | route별 허용 role 목록 | 서열 비교 (`atLeast`) |
| 토큰 저장 | `sessionStorage` | httpOnly 쿠키 |
| 비밀번호 | (확인 안 함) | scrypt, node 내장 |

역할을 넷에서 셋으로 줄인 건 professor와 ta가 하는 일이 거의 같았기 때문입니다. 강의별로
누가 관리자인지는 `problemset_members.role`로 나타냅니다. 전역 역할과 문제집 내 역할을 분리한
셈입니다.

## KOJ에서 가져온 것

바꾸지 않은 판단들입니다.

- **PostgreSQL.** 바꿀 이유가 없습니다.
- **채점을 별도 프로세스로 분리.** API가 채점을 기다리지 않는 구조는 그대로입니다.
- **컨테이너 격리 + isolate 계열 샌드박스.** KOJ는 `libjudger.so`(QingdaoU), 여기는 `isolate`(IOI).
  둘 다 같은 커널 기능을 씁니다.
- **정적 파일 SPA 배포.** nginx로 `dist`를 서빙하는 흐름을 유지했습니다. 운영 스크립트를
  거의 그대로 쓸 수 있습니다.
- **문서를 저장소에 둔다.** KOJ의 인수인계 문서가 이 프로젝트를 설계하는 데 결정적이었습니다.

## 아직 없는 것

KOJ에 있고 여기 없는 기능입니다. 필요하면 추가해야 합니다.

- **빈칸 채우기(blank)와 구현(implement) 문제 유형.** 여기는 표준 입출력 문제만 다룹니다.
- **퀴즈.** 객관식 문항 기능이 없습니다.
- **테스트케이스 zip 일괄 업로드.** 지금은 JSON으로 전체 교체만 됩니다.
- **성적 CSV 내보내기.** 진행 현황 API는 있지만 CSV로 떨구는 경로가 없습니다.
- **운영 제어 스크립트.** KOJ의 `koj.ps1`, `kojctl.sh`, `kojdb.sh`에 해당하는 것이 없습니다.
- **문제 본문 마크다운과 KaTeX 렌더링.** 지금은 평문으로 그립니다.
